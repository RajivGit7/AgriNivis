About AgriNivis

Useful intelligence, close to the field.

AgriNivis is a student-built agriculture platform with two practical goals: help farmers recognise crop disease earlier, and help them choose a crop that fits the land, water and season they actually have.

Why it exists

Advice is often scarce exactly when it matters.

A farmer may notice yellowing or lesions days before an extension officer can visit. By then, a disease can spread across a field or a whole village. The same gap affects planting decisions: seed is bought before the season's water and weather are fully known.

AgriNivis puts a lightweight vision model and a transparent crop suitability engine in the browser, so the first check is fast, explainable and available without an account.

Collect and prepare

Curate labelled leaf images across apple, rice, corn and grape; clean duplicates and standardise the label set.

Train and compress

Use transfer learning on a compact convolutional backbone, then export a quantised TFLite model for CPU inference.

Deploy separately

Serve the model from an independent container API, while the website remains a static GitHub Pages site.

Model details

From leaf pixels to a ranked diagnosis.

The classifier is deliberately compact: a 224×224 RGB image enters a convolutional network, and a softmax layer returns a probability for each of the 12 supported classes.

Input pipeline

EXIF orientation is corrected, the image is converted to RGB, bilinearly resized to 224×224, and scaled to [0, 1] as float32. The service validates content type and size before inference.

Inference

The TFLite interpreter runs on CPU with a single worker, keeping the API cheap enough for a free hosting tier. Predictions return the top three probabilities plus a low-confidence flag below 60%.

Knowledge layer

Each class is linked to a curated entry with pathogen, favourable conditions, symptoms, prevention, treatment and an agronomist note. Guidance is educational and avoids pesticide dosage instructions.

Separate deployment

The model lives behind its own API.

GitHub Pages can only serve static files, so the ML service is deployed independently as a Docker container. The website calls /health and /predict, and the API URL is configurable at runtime. This keeps the site fast while letting the model scale or move without a frontend rebuild.

Responsible use

What AgriNivis can and cannot do.

Privacy

Photos are sent to the inference API only when you press Analyse. The service processes them in memory and does not build a user profile or image archive. Crop recommendations run entirely in your browser.

Limits

The classifier only knows 12 classes. It can be confidently wrong on an unseen disease, a poor photo or a different crop. It is not a substitute for a plant clinic, a soil test or an agronomist.

Safe treatment

Treatment guidance names active ingredients but never recommends a dosage. Always read the product label, respect pre-harvest intervals and follow local restrictions. Integrated pest management comes first.

FAQ

Common questions.

Does AgriNivis store my leaf photos?
The reference API processes an uploaded image in memory and returns a prediction. It does not write the image to disk or to a database. If you deploy your own fork, review and document your hosting provider's logging behaviour.
Why does the disease API need a separate service?
GitHub Pages is a static host: it cannot run Python or TensorFlow. The ML service is deployed separately and the static site calls it. This is also how real systems separate a model service from a web frontend, allowing each to scale independently.
How accurate is the model?
Accuracy depends on the dataset split, crop, disease and photo quality. The paper reports per-class precision, recall and F1 along with a confusion matrix. In the app, always read the confidence and the low-confidence warning rather than the label alone.
Is the crop recommendation a trained model?
No. It is a transparent knowledge-based scoring engine. This lets it use inputs that public crop datasets usually lack, such as previous crop, irrigation reliability and soil type, while explaining every point in the score. The disease classifier is the trained ML model.
Can I use this for my own project?
The repository includes the inference service, website, deployment workflow and paper draft. Check the licence in the repository before redistribution, and re-verify all agronomic guidance with local experts before using it with farmers.
